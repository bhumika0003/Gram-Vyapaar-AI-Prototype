## 🔗 SHARED CONTRACT (identical for all 4 team members — do not deviate)

**Response envelope — every endpoint returns:**
```json
{ "success": true, "data": { }, "error": null, "meta": { "demoMode": false, "generatedAt": "ISO-8601" } }
```
Error shape: `{ "success": false, "data": null, "error": { "code": "STRING", "message": "..." }, "meta": {} }`

**Data-confidence wrapper — every analytical (non-raw-input) field arrives wrapped like this. Render it as a small badge/tooltip wherever it appears:**
```ts
type Confidence = "VERIFIED" | "DATA_ESTIMATE" | "USER_INPUT" | "MODEL_ASSUMPTION" | "DEMO_SYNTHETIC";
interface ConfidenceValue<T> { value: T; confidence: Confidence; source: string; asOf?: string; note?: string; }
```
Badge style guide: VERIFIED = green, DATA_ESTIMATE = blue, USER_INPUT = gray, MODEL_ASSUMPTION = amber, DEMO_SYNTHETIC = purple with a "Demo Data" label. Never show a number without its badge if it came wrapped this way.

**Explainability block — render as an expandable "Why?" under major results:**
```ts
interface Explanation { result: string; why: string; dataSource: string; limitation: string; }
```

**Core entity:** every business idea a user runs is an `applicationId` (UUID). Your wizard creates it once (via `POST /api/applications`), then every subsequent screen sends that same `applicationId` to the relevant module.

**Roles:** `"ENTREPRENEUR" | "CHANNEL_PARTNER" | "ADMIN"` · **Languages:** `"en" | "hi"` (build the i18n system so more can be added later)

**Auth (dev mode):** the backend accepts `x-user-id` / `x-user-role` headers as a stand-in for real JWT cookies during independent development. Build your API client to send these from whatever local session state you keep (and to also send/receive real httpOnly cookies once the real backend is merged in — same client code either way, just add `credentials: 'include'` to fetch calls).

## DESIGN LANGUAGE

The product must read as **trustworthy, government-backed, and rural-user-friendly** — not a generic AI chatbot skin and not a generic SaaS dashboard.
- Clean cards, clear charts, readable typography, strong hierarchy on financial numbers, accessible color contrast, fully responsive (assume many users are on mid-range Android phones with patchy connectivity — keep bundle light, show skeleton loaders, and design gracefully for slow/failed network calls).
- Homepage's primary CTA is **"Analyze My Business"** — never lead with "Ask AI anything." The AI chat is a secondary panel that sits *on top of* the structured analysis, never the entry point (this is the master spec's explicit anti-chatbot requirement).
